# FIT5120 CalmPath US2.1 API

## 1. Scope

US2.1 supports:

1. Finding nearby refuges from Shogo's MySQL RDS table
   `backend_refuge_candidates`.
2. Looking up the stored matched address after the user selects a refuge.

The runtime does not read CSV files and does not call the City of Melbourne
Street API. Both endpoints keep their existing request and response contracts.

## 2. `GET /api/v1/refuges/nearby`

### Request

```text
GET /api/v1/refuges/nearby?latitude=-37.8136&longitude=144.9631&radius_m=5000
```

Query parameters:

| Parameter | Type | Description |
| --- | --- | --- |
| `latitude` | float | User latitude, from `-90` to `90` |
| `longitude` | float | User longitude, from `-180` to `180` |
| `radius_m` | float | Search radius, greater than `0` metres |

The query uses the MySQL RDS table `backend_refuge_candidates` and includes
only rows where `is_refuge_candidate = 1`. The backend calculates Haversine
distance using the row's `latitude` and `longitude`, filters by `radius_m`, and
sorts results by ascending distance.

### `type` mapping

| RDS `sub_theme` | API `type` |
| --- | --- |
| `Informal Outdoor Facility (Park/Garden/Reserve)` | `park` |
| `Library` | `library` |

Other `sub_theme` values are not returned.

### Successful response

The top-level response is a bare array. Each item contains exactly:

```json
[
  {
    "id": "ea40efc1f181c0943d97b001",
    "name": "Alexandra Gardens",
    "type": "park",
    "latitude": -37.8206051404251,
    "longitude": 144.971796067365,
    "distance_m": 1214.36
  }
]
```

Field mapping:

| RDS field | API field |
| --- | --- |
| `landmark_id` | `id` |
| `feature_name` | `name` |
| `sub_theme` | `type`, using the mapping above |
| `latitude` | `latitude` |
| `longitude` | `longitude` |
| Backend Haversine result | `distance_m` |

The nearby response does not include `address`.

## 3. `GET /api/v1/refuges/address`

This endpoint is called after the user selects a refuge.

### Request

```text
GET /api/v1/refuges/address?latitude=-37.795&longitude=144.958
```

Query parameters:

| Parameter | Type | Description |
| --- | --- | --- |
| `latitude` | float | Selected refuge latitude, finite and from `-90` to `90` |
| `longitude` | float | Selected refuge longitude, finite and from `-180` to `180` |

The request does not accept `landmark_id` or a custom address radius. The
backend queries `backend_refuge_candidates` using the supplied coordinates and
only accepts rows where `address_match_status = 'MATCHED'`.

Address fields are generated by the data pipeline and stored in the same RDS
row:

| RDS field | API field |
| --- | --- |
| `address` | `address` |
| `address_latitude` | `latitude` |
| `address_longitude` | `longitude` |
| `address_distance_m` | `match_distance_m` |
| `address_source` | `source` |

The maximum stored address matching distance is 319 metres. The backend does
not perform live address matching and does not call the City of Melbourne
Street API.

### Successful response

```json
{
  "address": "61 Royal Parade Parkville",
  "latitude": -37.79516121,
  "longitude": 144.95776822,
  "match_distance_m": 42.5,
  "source": "Shogo address matching"
}
```

### Error responses

Errors use FastAPI's standard format:

```json
{
  "detail": "Description"
}
```

| Status | Situation |
| --- | --- |
| `422` | Invalid, non-finite, or out-of-range coordinates |
| `404` | No matched address found for the selected refuge |

## 4. Frontend call sequence

1. Call `/api/v1/refuges/nearby` when the user searches.
2. Display nearby results without calling the address endpoint in a result loop.
3. When the user selects a refuge, call `/api/v1/refuges/address` with that refuge's latitude and longitude.

No frontend parameter change is required.

## 5. Data processing and runtime boundary

The RDS table is populated by Shogo's data pipeline. Nearby candidate flags,
refuge coordinates, address matches, match distances, and address sources are
read from the stored table values.

At runtime the backend reads MySQL RDS only. It does not read
`refuge_candidates.csv`, call the City of Melbourne Street API, use Google
Geocoding, or require a frontend/API key for these endpoints.
